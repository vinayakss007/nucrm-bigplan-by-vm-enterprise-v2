## How tickets arrive

Tickets can be created from multiple sources:

| Source | How it works |
|---|---|
| **Customer portal** | Customers log in and submit a ticket from their self-service dashboard |
| **Email** | If email-to-ticket is configured, inbound emails create tickets automatically |
| **Chat widget** | A live chat session can be converted to a ticket for async follow-up |
| **Manual** | An agent creates a ticket from the Tickets page or from a contact's detail view |
| **Automation** | A workflow action creates a ticket when conditions are met (e.g. SLA breach on a deal) |

## Creating a ticket manually

1. Click **New ticket** from the Tickets page
2. Set the subject and describe the issue
3. Link it to a contact (and optionally a company or deal)
4. Set priority: low, normal, high, urgent
5. Assign to an agent or team (or let assignment rules handle it)
6. Add tags if relevant

<Callout variant="note">
Linking a ticket to a contact means the agent can immediately see the customer's deal history, past tickets and invoices — no "let me look you up" required.
</Callout>

## Ticket from a contact view

On any contact's detail page, click **Create ticket**. The contact is pre-linked, and any recent context (last email, open deals) is visible in the sidebar as the agent works.

## Portal-submitted tickets

When a customer submits via the portal, the ticket is created with:

- Their authenticated identity (no need for verification)
- Priority set by the customer (which you can override)
- Attachments they uploaded
- Automatic notification to the assigned team
