# Public documentation system for NuCRM marketing site (v2)

This change adds a full public documentation site under `/docs` in the marketing layout: MDX pipeline (@next/mdx + rehype-slug + rehype-pretty-code + remark-gfm), docs infrastructure (sidebar, breadcrumbs, prev/next, right-side TOC, Cmd+K search), and 30 MDX articles across four sections. MDX is now imported server-side in the catch-all page component, producing static HTML at build time. Unpublished sections are gated from sidebar, search, and landing page via a `published` flag on each section.

**Watch for:** Within the four published sections, 12 articles are declared in the tree but have no corresponding MDX file — they appear in the sidebar and search results and navigate to "coming soon" placeholders (confirmed). The `rehype-autolink-headings` package remains in `package.json` as dead weight despite being removed from the MDX config (confirmed, minor). The `'use client'` layout wrapping a server-rendered page is architecturally valid but means the entire sidebar/search tree ships as JS even though its data is static (likely, performance consideration).

## High-level view

The MDX pipeline is now server-side: `loadMDX` in the catch-all page uses a dynamic `import()` within a server component, so article HTML is generated at build time via `generateStaticParams`. The v1 client-side rendering issue is resolved. The configuration uses only `rehype-slug` and `rehype-pretty-code` (no more `rehype-autolink-headings`), with custom heading components providing the anchor link UX independently.

The published-flag gating works at the section level: 12 of 16 sections are marked `published: false` and completely hidden from all navigation surfaces. However, within the 4 published sections, the article tree declares 42 articles total while only 30 MDX files exist. The remaining 12 are visible in the sidebar and searchable, leading to the "coming soon" fallback rather than a 404 or visual distinction.

The TOC now uses a `MutationObserver` to re-scan headings when DOM content changes, the `CopyButton` uses a scoped ref rather than a global query, and the platform detection for the keyboard shortcut hint is deferred to a `useEffect` to avoid hydration mismatches. All six v1 issues are addressed.

## Article-level ghost content in published sections

The `published` flag on `DocSection` gates entire sections from `getPublishedSections()`, which feeds the sidebar, search index, landing page, and `generateStaticParams`. This correctly hides the 12 unpublished sections. But within published sections, the article arrays include entries without MDX files:

- **Contacts**: `tags-and-filters`, `bulk-operations`, `contact-timeline`, `custom-fields`
- **Deals**: `pipeline-reports`, `deal-automation`, `multiple-pipelines`
- **Communication**: `email-warmup`, `bulk-email`, `email-sequences`, `chat-widget`, `call-logging`

These 12 articles appear in the sidebar navigation, show up in search results, and are included in prev/next linking. When visited, the server-side `loadMDX` catches the import error and returns `null`, rendering the "coming soon" card. The page doesn't 404 — it renders a real route with empty content.

The cleanest fix: either remove these entries from the tree until MDX files exist, or add a per-article `published` field and filter at the article level the same way sections are filtered. The latter is more future-proof for gradual content rollout.

## Client layout architecture

The docs layout declares `'use client'` because it uses `useState` for the mobile sidebar toggle:

```tsx
'use client';
export default function DocsLayout({ children }: { children: React.ReactNode }) {
  const [sidebarOpen, setSidebarOpen] = useState(false);
  // ...
}
```

This forces `DocsSidebar`, `DocsSearch`, and `DocsTableOfContents` (and all their imports, including the full `DOC_SECTIONS` tree and `lucide-react` icons) into the client bundle. The `children` prop still receives the server-rendered page content correctly — Next.js handles this — but the shell components add unnecessary JS weight for what is largely static content.

A lighter pattern: make the layout a server component, render the sidebar server-side, and extract only the mobile toggle button into a small client component that controls visibility via CSS or a context provider. This would keep the 40+ article titles and icon imports out of the client bundle.
