→Verdict in five lines

The codebase is disciplined; the failures are structural and silent. Fix these in order.

  1. Tombstoned users can reset their password and mint a session. Smallest security fix in the report (design report P0.4).
  2. Pool mode and tenant context disagree. Session pooling is the only mode the RLS design works under; webhooks still need an explicit system context (P0.1, P0.2).
  3. Two cron routes are scheduled nowhere, and production omits recurring invoices and lead warming. One manifest, one parity check, persisted run records (H7).
  4. A Redis blip can route jobs to pg-boss, which no process consumes. Delete the fallback; make “queued” mean a consumer exists (H8).
  5. Authorization is optional. 66 of 248 mutating tenant routes check nothing beyond “logged in”, the role catalog and the strings routes check are different vocabularies, and record_permissions has zero enforcement readers (H9).
Full evidence, severity ranking, and reproduction commands: ../reports/DESIGN-ISSUES-2026-10-31.md.

L2Request lifecycle: the tenant data path

The canonical path. One pinned connection carries a session-scoped tenant GUC; pgbouncer's DISCARD ALL is what keeps that GUC from reaching the next request.

  DB-->>S: rows filtered by app filter AND policy
  S-->>R: typed rows
  R-->>B: data envelope
  W->>G: release connection
Authorization is voluntary on this path (H9). After requireAuth, a route may call can(ctx, …), check ctx.isAdmin, run enforceFieldRead/Write — or nothing. 66 of 248 mutating tenant routes do the last. Identity is a choke point; authority is four parallel mechanisms with no rule saying which handler owes which.

L5Async work and realtime

Producers negotiate a backend; only one backend has a consumer. Realtime fan-out is a separate process sharing rooms through the Redis adapter.

Design note. lib/queue/index.ts can select pg-boss, but the only consumer in the repo is worker.ts (BullMQ). A Redis failure at the first call is cached for the process lifetime, so later jobs are accepted into a queue nothing reads (#401).

L7Control plane: how the architecture is enforced

38 bespoke guard scripts — none parses a TypeScript AST, though guard:pool-mode (#3404) is the first to parse its inputs structurally at all: compose YAML, not a line pattern. 37 of the 38 do run in some workflow (ci.yml covers 34: 31 by alias, 3 by bare node scripts/…), and the local pre-merge script runs 4 while nothing calls it.
